# Подготовленная выжимка к мануалу

Исходный PDF, DOCX, XLSX, TXT или файл изображения загружается для скачивания клиентом. При наличии подготовленного JSON бот индексирует **только JSON** и не извлекает текст из исходного файла. Привязка к станку, серийному номеру и устройству задаётся в форме сайта, а не внутри JSON. Выжимка сохраняется рядом с исходником в выбранном хранилище; клиенту выдаётся только исходник.

Формат версии 1: UTF-8 JSON до 5 МБ. Пример для скачивания находится в `TechSupportRagBot/wwwroot/templates/prepared-manual-v1.json`.

```json
{
  "schemaVersion": 1,
  "title": "Мануал устройства, редакция производителя",
  "sections": [
    {
      "id": "alarm-a003",
      "title": "Ошибка A003",
      "text": "Самодостаточное и проверенное описание значения ошибки, причин и безопасной последовательности действий из мануала.",
      "keywords": ["A003", "alarm A003", "ошибка A003"],
      "tags": ["диагностика", "сервопривод"],
      "questions": ["Что означает A003?", "Как устранить ошибку A003?"],
      "node": "Сервопривод",
      "errorCode": "A003",
      "operation": "диагностика",
      "cause": "Причина из руководства, если указана",
      "solution": "Действия из руководства, если указаны",
      "sourcePage": 42
    }
  ]
}
```

Текст в примере выше иллюстрирует **структуру**, а не утверждает значение реальной ошибки A003. Перед загрузкой каждый раздел нужно наполнить фактами из конкретного руководства.

## Правила подготовки

- Один элемент `sections` — одна законченная тема: код ошибки, параметр, процедура настройки, схема подключения или правило обслуживания. Разные коды и параметры не смешиваются в одном элементе.
- `text` содержит ответ, который бот может безопасно использовать сам по себе. Недостаточно записать только название, ключевые слова или ссылку на страницу. Не добавлять догадки, неочевидные настройки и неподтверждённые причины.
- `keywords` включает точные обозначения, коды, синонимы и распространённые варианты написания. `questions` содержит естественные вопросы клиента, на которые отвечает `text`. `tags` задаёт несколько общих тем. Эти поля помогают поиску, но не заменяют фактический ответ.
- `sourcePage` указывает страницу исходника, если она известна. Для одной настройки с несколькими значениями или режимами можно сделать несколько разделов, сохраняя конкретный контекст и страницу.
- Для ошибок полезны `errorCode`, `cause`, `solution`; для параметров — код в `keywords`, назначение, допустимые значения, условия изменения и последствия в `text`; для процедур — предусловия, шаги и проверки результата в `text`.
- Реклама, юридические шаблоны, повторяющиеся колонтитулы и оглавление не индексируются, если они не отвечают на технические вопросы. Не терять предупреждения по безопасности, ограничения и условия применимости.
- Отмечать неразборчивые страницы и спорные факты отдельно в рабочем отчёте; не заполнять их догадками в JSON.

## Проверки формата

`schemaVersion` равен `1`; `title` обязателен; `sections` содержит от 1 до 1000 элементов. В каждом разделе обязательны уникальный `id`, `title`, `text` длиной 40–6500 символов, хотя бы одно `keywords` и одно `questions`. Не более 30 ключевых слов, 30 тегов и 12 вопросов на раздел; отдельный элемент списка не длиннее 160 символов. `sourcePage`, если указан, положителен. Сервер проверяет формат до записи файла и повторно перед индексацией. Повторная загрузка выжимки ставит документ в очередь переиндексации.
